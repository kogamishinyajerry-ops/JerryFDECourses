# 课程地图 v1.0

## 总体结构

课程由六部分、十八个模块组成。模块顺序遵循：

```text
个人工作
→ 真实场景
→ 可信系统
→ 组织资产
→ 团队能力
→ 持续治理
```

公开课程使用通用、合成案例。真实专业适配在封闭环境中完成。

---

# 第一部分｜工程师如何进入 AI 时代

## M01｜从一条模糊需求开始

把一句“请帮我整理一下”，变成一张可以执行、可以确认的任务卡。

**构建结果**：任务卡、缺失字段、澄清问题、人工确认和运行记录。

## M02｜模型、程序、Agent 和 Harness 分别做什么

在 M01 的同一条流程中加入模型，只让它生成候选字段和澄清问题。

**构建结果**：候选提取器、确定性校验器、人工确认门禁和对比实验。

## M03｜FDE 的第一项能力：把工作说清楚

把一个日常任务拆成对象、动作、状态、判断和证据。

**构建结果**：个人工作地图与最小自动化切口。

---

# 第二部分｜完成第一个真实 Agent 项目

## M04｜进入现场：用户说的需求和真实工作

通过观察、访谈和样例回放，发现用户请求背后的真实工作链。

**构建结果**：用户工作地图、问题假设和证据清单。

## M05｜判断这个问题是否适合 Agent

评估价值、边界、可回滚性、数据、风险、Owner 和验收条件。

**构建结果**：Go / Narrow / No-Go 决策卡。

## M06｜构建第一个可以被试用的 MVP

只实现一条主路径和一条失败路径，交给真实用户试用。

**构建结果**：可运行 MVP、基线、反馈记录和继续/停止决定。

---

# 第三部分｜把 Demo 变成可信工程能力

## M07｜对象与关系：建立最小本体切片

把散落在文本、表格和个人经验中的对象与关系变成共享语义。

**构建结果**：最小本体、对象字典和约束。

## M08｜状态机：让任务知道自己走到哪里

处理等待、失败、重试、转人工、完成和取消。

**构建结果**：状态图、转移条件、恢复规则和事件记录。

## M09｜工具契约：把确定性能力接进来

定义工具输入、输出、错误、权限、幂等性和可观察性。

**构建结果**：Tool Contract、Mock 工具和契约测试。

## M10｜Human-in-the-loop：把责任留在正确的位置

区分建议、确认、批准、签发和异常接受。

**构建结果**：决策权力矩阵和人工门禁。

## M11｜评测与证据：怎样知道系统值得继续用

建立基线、测试集、失败类型、Trace 和证据包。

**构建结果**：Eval Pack、回归测试和运行证据。

## M12｜错误、恢复与回滚

让系统在输入错误、工具故障、模型不确定和版本退化时可控失败。

**构建结果**：故障注入、恢复演练和回滚说明。

---

# 第四部分｜把一次项目变成 Agent 资产

## M13｜Agent Asset Package

将业务契约、本体、工作流、工具、策略、评测和运行说明整理为标准资产包。

**构建结果**：可校验资产目录与 Manifest。

## M14｜方法适用域与版本边界

说明能力在哪些条件下有效，哪些条件下必须停止或升级人工。

**构建结果**：适用域、已知限制、兼容矩阵和发布说明。

## M15｜接入 Harness，但不绑定 Harness

为资产增加 Runtime 适配器、Sandbox、Trace 和生命周期管理。

**构建结果**：Harness 适配器、安装说明和替换实验。

---

# 第五部分｜从个人 FDE 到高价值团队

## M16｜角色、结对与接手

建立领域、集成、评测和 Lead 的协作方式，消除作者单点依赖。

**构建结果**：角色责任表、结对计划和接手演练。

## M17｜四类评审与失败复盘

开展业务、架构、代码和评测评审，把失败转化为团队资产。

**构建结果**：评审记录、复盘和教材更新项。

---

# 第六部分｜FDE 团队管理与治理

## M18｜项目组合、发布门禁与学习速度

管理 WIP、项目停止、权限、版本、事故、指标和人才成长。

**构建结果**：团队运行规章、项目组合看板和季度学习报告。

---

# 三条学习路径

## 工程师入门路径

```text
M01 → M02 → M03 → M04 → M05 → M06
```

完成标准：交付一个可试用的小型工作流。

## 工业 FDE 路径

```text
M01–M12
```

完成标准：系统具备对象、状态、工具契约、人工门禁、评测和恢复能力。

## 资产负责人 / FDE Lead 路径

```text
M01–M18
```

完成标准：资产可以发布、复用、接手，并进入团队治理。

# 项目阶梯

| 阶段 | 典型产出 | 关键问题 |
|---|---|---|
| P0 | 个人任务闭环 | 能否运行和检查？ |
| P1 | 小范围场景 MVP | 是否有人真实使用？ |
| P2 | 可信 Agent | 是否能发现错误并保留责任边界？ |
| P3 | 标准 Agent 资产 | 是否能被另一名 FDE 安装和复用？ |
| P4 | 团队运营资产 | 是否有 Owner、版本、门禁、指标和接手人？ |

# 课程版本策略

- 模块设计卡先于完整逐字稿；
- 可运行实验先于视觉包装；
- 失败样例与正常样例同时进入版本；
- 首期学员反馈直接形成 Issue 与 ADR；
- 课程更新以真实使用和评测变化为依据。
