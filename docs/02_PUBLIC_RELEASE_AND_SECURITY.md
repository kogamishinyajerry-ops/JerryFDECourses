# 公开发布与保密规范 v1.0

## 1. 总原则

本仓库是公开仓库。任何提交都按照“可以被完整复制、长期缓存和再次传播”处理。

课程案例必须满足：

> 代码、数据、截图、日志、讲稿和生成提示词一并公开，也不会暴露内部业务能力、工具链或人员信息。

无法直接确认安全的材料，不进入公开主课。

## 2. 禁止提交

### 工程与业务信息

- 真实型号、项目、构型、参数、阈值和结果；
- 实际性能、仿真、试验、控制或健康管理数据；
- 内部工作流程、评审关系、故障模式和批准逻辑；
- 可以组合推断业务能力的目录、字段和运行顺序。

### 工具与系统信息

- 专有软件真实界面与未公开配置；
- 内部脚本、模板、输入格式和接口协议；
- 内网地址、主机名、端口、拓扑和账号；
- 许可证、密钥、Token、Cookie 和认证信息；
- 真实日志、报错堆栈和目录结构。

### 人员与组织信息

- 未经授权的姓名、工号、邮箱、组织关系和职责；
- 会议录音、转写、聊天记录和内部截图；
- 能够识别个人或团队的任务分配与评审记录。

## 3. 公开案例分层

### A. 公开主课

使用完全虚构的任务、数据和工具。

要求：

- 不依赖内部背景；
- 学员可在个人电脑复现；
- 使用通用文件格式；
- 代码可开源；
- 失败样例同样安全。

### B. 企业适配练习

学员只提交结构映射：

- 对象类型；
- 字段类型；
- 状态；
- 责任边界；
- 检查方法。

不得提交真实文件、参数、截图和项目名称。

### C. 封闭实战

真实专业工具、数据和流程只能在经授权的封闭环境中开展。

封闭实战材料：

- 不上传本仓库；
- 不用于公开录屏；
- 不发送外部模型；
- 按组织内部数据等级和审批流程管理。

## 4. 脱敏不足的常见误区

以下做法仍然可能泄密：

- 只替换项目名称，保留真实字段和参数范围；
- 使用“模拟程序”，但复刻真实输入格式和运行顺序；
- 隐藏数值，保留内部软件界面；
- 打码截图，但保留目录、标签和工具链；
- 公开一段看似普通的代码，其中包含真实业务规则；
- 把多个独立片段分别发布，组合后可以还原流程。

## 5. 发布前检查

每次公开发布至少回答：

1. 这份材料是否来自完全合成数据？
2. 是否出现真实工具名、内部目录、接口或软件画面？
3. 字段、状态和阈值是否可能映射到真实工程方法？
4. 是否包含姓名、账号、地址、密钥或组织关系？
5. 代码和日志是否暴露环境信息？
6. 多份文件组合后，是否可以推断内部能力？
7. 是否存在许可证、版权或第三方数据限制？
8. 一名不知情的审查者能否确认其来源和边界？

任何一项答案不清楚，停止发布。

## 6. 课程中的边界声明

所有公开模块必须包含类似说明：

> 本模块使用合成案例，用于演示任务建模、状态、校验和人工确认。它不包含真实工程数据、专业工具链或内部流程，也不构成任何工程批准或业务决策依据。

## 7. 自动检查

仓库 CI 至少检查：

- 常见密钥格式；
- 私网 IP、URL 与邮箱；
- 高风险工程关键词；
- 大型二进制和未知文件；
- 课程模块是否包含公开边界声明。

自动检查只能发现部分风险，不能替代人工审查。
