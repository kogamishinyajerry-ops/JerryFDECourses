# 项目宪章｜AI 时代的工业 FDE

## 1. 项目使命

培养一批能够把专业工作转化为可信 AI 能力的工程师，并让这些能力可以被团队继承、复用和持续改进。

课程不把“学会一个框架”或“做出很多 Agent”作为终点。真正的完成条件是：

- 学员能找到真实问题；
- 能把工作拆成明确对象、步骤和边界；
- 能构建并运行一个最小闭环；
- 能发现错误，知道系统何时应该停止；
- 能留下验证证据；
- 能把成果整理为另一名工程师可以接手的资产。

## 2. 核心判断

企业长期稀缺的能力来自：

```text
高密度 FDE 人才
×
成熟的问题解决方法
×
可复用的领域资产
×
持续学习的团队机制
×
轻量可靠的技术底座
```

平台是放大器。人才、方法和资产才是课程中心。

项目原则：

> 轻平台、厚人才、厚资产。

## 3. 主要学习者

### 路径 A｜AI 入门工程师

当前状态：会使用聊天模型，尚未形成可运行的工作流。

目标：完成一个边界清楚、能够检查的个人工作闭环。

### 路径 B｜FDE 候选人

当前状态：具备专业经验，愿意写代码、接工具并面对真实用户。

目标：独立交付一个经过验证的小型 Agent 场景。

### 路径 C｜FDE 骨干与负责人

当前状态：做过项目，但团队协作、评测、资产和治理仍不稳定。

目标：带领小团队持续交付，并减少单点依赖。

## 4. FDE 能力模型

课程培养七项能力：

1. **领域判断**：知道什么值得做、什么结果不能接受；
2. **问题建模**：把模糊请求变成对象、状态、责任和验收；
3. **AI 与自动化实现**：使用模型、脚本、API、工具和 Harness；
4. **工程校核**：检查输入、适用性、结果、证据和异常；
5. **用户共创与交付**：进入现场，观察真实工作并持续修改；
6. **资产化**：把个人脚本转化为工作流、契约、评测和文档；
7. **协作与带教**：让其他人能够评审、复现和接手。

## 5. 成长阶梯

| 等级 | 状态 | 可观察表现 |
|---|---|---|
| L0 | AI 使用者 | 会提问、会核查、不盲信 |
| L1 | AI 增强工程师 | 能自动化自己的一个重复任务 |
| L2 | 场景构建者 | 能为小范围用户交付可试用工作流 |
| L3 | 工业 FDE | 能独立处理业务、技术、验证与推广 |
| L4 | 资产负责人 | 能维护一组可复用资产和评测 |
| L5 | FDE Lead | 能培养人、选项目、治理质量与资产 |

## 6. 课程结构

### 第一部分｜工程师如何进入 AI 时代

从自己的工作开始，理解模型、Agent、工具、Harness 和 FDE 的位置。

### 第二部分｜完成第一个真实 Agent 项目

进入现场、识别问题、判断是否适合 Agent 化、构建 MVP 并与用户共创。

### 第三部分｜把 Demo 变成可信工程能力

建立本体、状态机、工具契约、人工门禁、错误恢复、评测和证据。

### 第四部分｜把一次项目变成 Agent 资产

形成标准资产包、适用域、版本、发布、回滚和 Runtime 适配器。

### 第五部分｜从个人 FDE 到高价值团队

建立角色、评审、带教、共享资产和交接机制。

### 第六部分｜FDE 团队的管理与治理

管理项目组合、权限、发布、事故复盘、团队指标和学习速度。

## 7. 教学方式

课程采用：

```text
20% 方法讲解
60% 构建与真实项目
20% 同行评审与复盘
```

每个模块必须包含：

- 一个具体对象；
- 一次可见运行；
- 一个失败或边界；
- 一次修改；
- 一份学员资产；
- 一次评审。

## 8. 北极星指标

不使用 Agent 数量作为主要成绩。

课程与团队共同追踪：

- 能独立交付的 FDE 数量；
- 通过可信性评审的项目数量；
- 资产被另一名工程师成功接手的比例；
- 真实用户重复使用率；
- 人工修改率与故障逃逸率；
- 既有资产复用率；
- 新人从 L0 到 L2 的时间。

## 9. 明确不做

本项目不承诺：

- 建成覆盖所有业务的万能 AI 平台；
- 让学员一次掌握所有技术栈；
- 用模型替代工程责任人；
- 用 Demo、视频效果或功能数量替代真实验证；
- 在公开仓库展示内部工具链和专业敏感实现。
