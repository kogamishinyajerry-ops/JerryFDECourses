# M01 Image-2 视觉提示词

这些提示词用于生成概念探索图、封面和过渡画面。正式技术步骤仍以 HTML/CSS/SVG 和真实屏幕录制为准。

## 统一约束

每条提示词都应包含：

```text
公开课程、完全虚构数据、无真实公司标识、无专业软件界面、无工程参数、无内网信息、无机器人主体、无发光大脑、无赛博朋克背景、可读性优先、16:9
```

## V01｜课程封面

```text
一张现代、克制、工程师气质的中文技术课程封面，标题“从一条模糊需求开始”，副标题“把一句帮我整理一下，变成一张可以执行、可以确认的任务卡”。画面中心是一个简单文本文件，经过几个清晰步骤变成结构化任务卡：原始请求、缺失字段、澄清问题、人工确认、READY。深色窄侧栏，白色工作区，扁平矢量风格，编辑器与文件卡片元素，留出真人标题叠加空间。公开课程、完全虚构数据、无真实公司标识、无专业软件界面、无工程参数、无内网信息、无机器人主体、无发光大脑、无赛博朋克背景、可读性优先、16:9。
```

## V02｜静默默认值

```text
技术教学信息图。左侧是一句模糊任务请求，右侧是一张看似完整的任务卡。PPT、NEXT_FRIDAY、CURRENT_USER 三个字段带红色虚线，标注“系统默认，未经确认”。状态灯显示 READY，但旁边有一个克制的问号。画面要表达程序运行成功、任务语义却不可靠。扁平矢量、白色背景、少量深蓝与红色，中文标注清楚。公开合成案例，无真实系统和公司信息，16:9。
```

## V03｜缺失信息变成问题

```text
一张逐步构建的流程图：模糊请求进入任务卡，空白字段 source、time range、output、due date、owner、acceptance criteria 被抽出，转化为六条澄清问题。画面重点是字段到问题的一一对应，使用简洁卡片和细线，不使用人物或机器人。白色工作区、深色左侧导航、蓝色明确字段、灰色未知字段、琥珀色澄清状态。公开课程，16:9。
```

## V04｜人工确认与来源

```text
技术课程信息图，展示同一任务卡中的三种字段来源：蓝色 SOURCE_TEXT、红色 SYSTEM_DEFAULT_UNCONFIRMED、绿色 HUMAN_CONFIRMED。人工确认后，红色默认值被划掉，绿色值进入任务卡，状态从 NEEDS_CLARIFICATION 变为 READY。扁平、清楚、克制，不使用握手、机器人或抽象 AI 光效。16:9。
```

## V05｜READY 的窄定义

```text
一张极简状态解释图。中央是绿色 READY 状态，下面写“必填信息已确认，可进入执行准备”。右侧灰色列出仍未发生的事情：任务未执行、交付未评审、结果未发布、责任人未签发。视觉传达状态必须与证据匹配。现代工程软件界面风格，白底、绿色和灰色，16:9。
```

## V06｜M02 预告

```text
M01 到 M02 的过渡图。已有流程为原始请求、候选任务卡、规则检查、人工确认、READY。一个灰色的“模型”模块被放入原始请求与候选任务卡之间，并明确标注“只生成候选，不批准事实”。简洁线性流程，扁平矢量，面向工程师的技术课程画面，16:9，无品牌和真实数据。
```

## 资产使用规则

- 生成图用于封面、章节过渡和社交传播；
- 技术字段、代码和状态图用可编辑资产重绘；
- 生成图中的文字必须人工复核；
- 不把生成图当作真实软件截图；
- 不在生成提示词中输入任何内部材料；
- 生成结果进入仓库前执行公开安全检查和版权检查。
