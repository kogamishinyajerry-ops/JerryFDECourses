# M01 模块设计卡

| 字段 | 内容 |
|---|---|
| 模块编号 | M01 |
| 标题 | 从一条模糊需求开始 |
| 副标题 | 把一句“请帮我整理一下”，变成一张可以执行、可以确认的任务卡 |
| 课程位置 | 第一部分第 1 模块 |
| 学习者 | L0、L1 候选人 |
| Main Lesson | 26–30 分钟 |
| Build Lab | 45–60 分钟 |
| 前置要求 | Python 3.10+；无需第三方依赖 |
| 强制产出 | 任务卡、澄清问题、人工确认、运行记录 |
| 风险等级 | 公开、低风险、完全合成案例 |
| 下一模块 | M02：加入模型生成候选信息 |

## 学习目标

完成课程后，学员能够：

1. 从原始请求中只提取明确存在的信息；
2. 区分事实、候选和确认值；
3. 定义任务进入执行前必须具备的字段；
4. 生成有针对性的澄清问题；
5. 让任务在信息不足时停留在 `NEEDS_CLARIFICATION`；
6. 通过人工确认把任务推进到 `READY`；
7. 保留可回看的运行记录。

## 本集对象

```text
request.txt
```

内容：

> 请把上个月收到的用户问题整理一下，下周评审时用。

## 关键失败

v0 为缺失信息静默补充：

```text
expected_output = PPT
owner = CURRENT_USER
due_date = NEXT_FRIDAY
```

任务错误进入 `READY`。

## 本集修改

v1 删除静默默认值，引入：

- 必填字段；
- 明确缺失清单；
- 澄清问题；
- 人工确认来源；
- 运行证据。

## 延后命名的概念

学员先经历流程，再在结尾引入：

- 输入契约；
- 状态；
- Human-in-the-loop；
- Trace / Evidence；
- 责任边界。

## 教学顺序

```text
原始请求
→ 人工读取
→ v0 静默猜测
→ 暴露问题
→ v1 停止
→ 生成问题
→ 人工确认
→ READY
→ 查看记录
→ 给概念命名
```

## 本集明确不做

- 不调用真实模型；
- 不讲 Prompt 技巧；
- 不创建聊天机器人；
- 不接入企业系统；
- 不展示专业或涉密工具；
- 不把 `READY` 描述为任务完成。

## Main Lesson 完成标准

- 前 2 分钟出现 `request.txt`；
- 前 8 分钟运行 v0；
- 课程中保留错误输出；
- v1 运行两次：一次停止，一次 READY；
- 结尾回到本轮生成的四份文件。

## Build Lab 完成标准

- 所有单元测试通过；
- 学员能修改自己的安全样例；
- 缺失必填字段时退出码非 0；
- `READY` 状态包含确认来源；
- 运行记录区分原始请求、系统提取和人工确认。

## 学员作业

提交目录：

```text
m01_<task_name>/
├── README.md
├── input/request.txt
├── confirmation.json
├── output/task_card.json
├── output/questions.md
└── output/run_record.json
```

## 评分 Rubric

| 维度 | 2 分标准 |
|---|---|
| 安全与真实性 | 结构来自真实工作，但样例完全虚构或彻底脱敏 |
| 边界 | 能说明任务何时不能开始 |
| 可复现 | 另一名同学可以运行 |
| 人工确认 | 猜测没有被写成事实 |
| 证据 | 原始请求、问题、确认和状态可回看 |

7 分及以上进入 M02。低于 7 分先缩小任务或补齐失败路径。
