# M01 真人素材交接单

## 使用方式

M01 的技术主轨已经可以独立理解。真人素材只承担三项工作：

1. 建立主讲人与课程的关系；
2. 亲自说明作业的公开安全边界；
3. 收束本集，并把问题交给 M02。

真人镜头不承担复杂概念解释，也不需要展示任何真实工作环境。

建议总真人时长：55–75 秒。

## 统一录制设置

- 画幅：16:9，4K 或 1080p；
- 帧率：25 或 30 fps，全片统一；
- 景别：中近景，眼睛位于画面上三分之一附近；
- 背景：简单、安静，不出现公司标识、项目资料、白板内容或可识别屏幕；
- 服装：无组织 Logo、无胸牌、无型号或项目元素；
- 收音：领夹麦或近距离指向麦；
- 每条录两遍，前后各留 3 秒静止；
- 关闭手机、电脑和门禁提示音；
- 不在画面中展示真实文件、账号、日历和通知。

文件命名：

```text
M01_H01_opening_v01.mov
M01_H02_assignment-safety_v01.mov
M01_H03_closing_v01.mov
```

## H01｜开场

**建议时长：18–24 秒**

### 前一画面

课程标题页：

```text
M01｜从一条模糊需求开始
```

### 台词

> 这一节，我们从一条很普通的工作消息开始。
>
> 没有模型排行榜，也不搭 Agent。
>
> 先看文件。

### 表演与剪辑

- 第一句正常语速；
- 第二句可以略停；
- “先看文件”说完停一秒；
- 随后硬切到 `request.txt`，不加宏大转场；
- 不需要手势指向屏幕。

### 后一画面

打开：

```text
modules/M01/lab/data/request.txt
```

## H02｜作业与安全说明

**建议时长：22–30 秒**

### 前一画面

M02 预告之前，先出现作业文件清单：

```text
request.txt
confirmation.json
task_card.json
questions.md
run_record.json
```

### 台词

> 从自己的工作里找一句常见请求。
>
> 不要上传真实内部内容。保留句子结构，替换人名、文件、日期和项目。
>
> 提交一条安全样例，再加一个系统必须停止的条件。
>
> 第一版控制在一个小时以内。

### 表演与剪辑

- “不要上传真实内部内容”单独成句；
- 屏幕同步显示四类替换项：人名、文件、日期、项目；
- 不举真实工作案例；
- 台词结束后切回作业页面。

### 后一画面

展示：

```text
lesson/ASSIGNMENT_AND_RUBRIC.md
```

## H03｜结尾

**建议时长：18–24 秒**

### 前一画面

并列显示：

```text
task_card.json
questions.md
run_record.json
status.txt
```

### 台词

> 这一集只做了一张任务卡。
>
> 它能区分已知和未知，缺信息会停，确认以后能继续，过程也留了记录。
>
> 下一集，我们让模型进入这条流程。

### 表演与剪辑

- 不作课程使命升华；
- 最后一句后停一秒；
- 切到 M02 灰色候选模型框；
- 片尾状态仍写 `M01 · PILOT` 或 `RC`，在正式发布前不要写 `v1.0 RELEASED`。

## 备选：没有真人素材时

课程可以先制作内部预览版。三个真人插槽分别替换为：

### H01 替代卡

```text
这一节从一条工作消息开始。
先看文件。
```

### H02 替代卡

```text
只使用虚构或彻底脱敏的请求。
不要上传真实内部内容。
```

### H03 替代卡

```text
M01：确定性任务准备骨架
M02：模型只生成候选
```

替代卡只能用于内部预览和试剪。正式版是否保留真人镜头，由课程负责人在试讲后决定。

## 素材验收

每段素材检查：

- [ ] 画面没有组织、项目和系统信息；
- [ ] 台词与讲师稿一致；
- [ ] 无口误、断句和爆音；
- [ ] 前后留足剪辑余量；
- [ ] 文件名符合约定；
- [ ] 色温、构图和收音三段一致；
- [ ] 没有把 `READY` 说成任务完成；
- [ ] 没有宣称课程已经正式发布。
